### v1.6.0：跳过按钮没有文字怎么办（2026-11-25 真机实测）

用户截图里的那条开屏广告（小红书投放给 WakeUp 课程表）从未被跳过。
`uiautomator dump` 出来是这样的：

```
View     clickable=true  150×150 @ [60,2326]   ← 跳过按钮，text/desc/id 全空
TextView clickable=true  120×53  @ [75,2517]   ← 「广告」小标签，同样全空
id_splash_bottom_logo                          ← 穿山甲固定 id
desc=NativeVideoAdView
text="向上滑动" / "跳转至详情页或第三方应用"
```

整页只有 2 个可点节点，都没有文字——「跳过」两个字是 Canvas 画的。
任何关键词匹配都必然漏掉，这不是阈值问题，是证据类型不对。

做法（`engine/DrawSkip.kt`，纯函数，12 个单测）：

* **形状**：长宽比 ≥ 0.70、短边落在屏短边的 4%~20%、水平中心在左右各 32%
  内、避开状态栏与导航条。那条 120×53 的标签因为比例 2.26 被排除。
* **强标记**（必须同时成立其一）：`splash` 类 id、`NativeVideoAd/AdView`
  描述、「向上滑动 / 跳转至详情页 / 点击到落地页」模板文案。
* 三条前置：在开屏窗口 6 秒内、页面不是内容页、本轮没点过。

真机结果：5 次冷启动 5 次跳过，其中 3 次走自绘判据，命中矩形
`Rect(60, 2326 - 210, 2476)`，与 dump 出来的按钮位置逐像素一致。

### 真机实测改掉的两处设计（2026-11-25，Redmi 24122RKC7C / Android 17 / HyperOS 4.0.3）

1. **撤销按钮根本点不到**。v1.3.11 用 `IMPORTANCE_LOW`，被 Android 17 归进
   `Aggregate_SilentSection`，`uiautomator dump` 的节点树里**根本没有**
   「撤销 / 不再提示」——不是被遮住，是没渲染。改成 `IMPORTANCE_DEFAULT`
   + 静音 + 新渠道 `adskip_guard_v2`，并把**点通知本体**接成撤销（正文写
   「点此撤销」），双保险。
2. **轮询路径拿不到 className**。`TEST J`（下拉通知栏 → 点通知）在当前 ROM 上
   只发 `TYPE_WINDOW_CONTENT_CHANGED`（2048），没有 `WINDOW_STATE_CHANGED`；
   轮询兜底能发现 `pkg=com.android.systemui`，但传的是 `className=null`，
   `isUserSurface(null)` 恒为 false → 来源不会被清空。**这是已知缺口**，
   v1.4.0 未修（需要新的「屏幕被遮住多少」信号，不能靠猜），记在下面。

### 实测拿到的 M2b 数据（点击事件派发率）

| 场景 | 是否派发 `TYPE_VIEW_CLICKED` | 证据 |
|---|---|---|
| 原生界面（淘宝首页） | 是 | `evt type=1` + `input tap pkg=com.taobao.taobao fullscreen=false` |
| 系统 UI（通知栏） | 是 | `input tap pkg=com.android.systemui` |
| 自家跳过（ACTION_CLICK） | 是（被过滤） | `input tap pkg=... ignored=self 148ms` |
| WebView 页面 | 未测成（测试页没加载出来） | — |
| 摇一摇 | 否（本来就没有点击） | 交给 R12 |

结论：R4 至少对原生界面有效；自家点击的 600ms 过滤**实测生效**，
不会把一次自动跳过变成假用户点击。

v1.3.10 落地时与本文有两处差异，都记在对应小节里：

## 0. 我核对了什么

报告的四个缺陷，逐条对着源码查过，**全部成立**：

| 编号 | 代码位置 | 核对结果 |
|---|---|---|
| D1 | `JumpGuard.kt:188` | 确认。`pkg == "com.android.systemui"` 直接 `return`，不动 `originPkg`；而 `calcCold()`（`SkipAccessibilityService.kt:727`）对 passThrough 包返回 true |
| D2 | `GuardDecision.kt:442` | 确认。`c.destIsStore -> true`，连 `originSettled` 都不看 |
| D3 | `GuardDecision.kt:455` | 确认。`originShowingSplash || dt <= 2500` 给了「零正面证据」的降级通道 |
| D4 | `SkipAccessibilityService.kt:69` | 确认。`NEVER_SCAN` 仍在 service 内，`isInUserBlocklist` 在 JumpGuard 内另算 |

另外三处报告没写、但会影响实施的细节：

1. `reset()` 不清 `lastBackAt`（有意为之），所以 R1 直接复用 `reset()` 是安全的，不会把「防连按冷却」一起清掉。
2. `accessibility_service_config.xml` 的 `notificationTimeout="80"` 是**同一事件类型**的最小间隔，点击有自己的节流桶，理论上不会被内容变化事件挤掉；但「WebView 内点击是否派发」「80ms 内连点会不会被合并」都还没验证（见 M2/M2b）。
3. 报告 R5 的指纹表里有 `"ad_"` 这种裸子串，会误命中 `download_`、`loading_`、`badge_`。指纹必须按 SDK 前缀 + 词边界匹配，不能裸子串。
4. 排除自家动作所需的「上一次自家点击时间」其实已经存在（`SkipAccessibilityService.lastClickAt`），但它只在 `Access.click` 之后更新（L1221）；坐标点击（L1249）、三处返回动作（L526 / L1216 / L1331）都没更新。R4 如果不补齐这四处，一次自动跳过就会造出一个假「用户点击」。

## 1. 三处我不按报告做

### 1.1 R4 的代价被低估了：点击型广告本身就会派发 click

报告说「有点击就是用户自己点的」，但**点击型广告的容器也是一个普通 View**，点任意位置跳转时 `TYPE_VIEW_CLICKED` 照样会派发。照报告的写法，这类广告会从「拦」直接变成「不拦」——不是漏一点，是整整一类失效。

**改法**：点击只记时间戳，但**在冷启动 3 秒内**额外读一次 `e.source` 的边界（一次 IPC，可接受）：

```
点击目标覆盖屏幕 > 85%  → 判为 adClick，不作为「用户输入」
其余                    → 正常记为用户输入
```

商品卡、按钮的面积远小于全屏。这样既保住了「点商品卡不拦」，也保住了「点广告仍然拦」。

### 1.2 R6 不直接把「严格」设为默认

报告计划 v1.4.0 默认严格档（LOW 不回退，只提示）。问题是：**LOW 里本来就有真广告**，一旦默认严格，用户看到的就是「没以前跳得勤」，等于用新问题换旧问题。

**改法**：v1.4.0 默认**兼容档**（判定与处置都保持现行为），严格档放在设置里并标注「误拦更少、可能漏拦」。翻默认的条件写死，不靠感觉：

> 影子模式连续 7 天，LOW 档里「拦截后 10 秒无回访」的比例 ≥ 80% 才翻默认。
> 低于这个数说明 LOW 里真广告太多，翻了就是制造漏拦投诉。

### 1.3 R8 的「relaunch 提为第 1 级」不做

把「拉起原 App」当第一级（120ms）确实最快，但 `startActivity` 会**把落地页任务留在后台**：用户下次从图标进原 App，可能先看到那张券页。而且转场动画期间有竞态。收益 200ms，代价是一个新的、难解释的 bug。

**改法**：只做两件低风险的事——
- 窗口事件到达时立刻排一次 **80ms** 的返回（400ms 那一路保留作兜底，每次动作前复核前台包名）；
- `relaunch` 从 1.6s 提前到 **1.2s**。

## 3. v1.3.10：收敛结构 + 修 bug + 度量

### 3.1 R9｜`AppRole` 单一分类源（纯重构，行为不变）

**改哪儿**

`data/AppLists.kt`：

```kotlin
enum class AppRole { SHELL, SYSTEM_UI, BROWSER, STORE, LANDING, CONTENT, USER_DRIVEN, AD_PRONE, INERT }

fun roles(pkg: String): Set<AppRole>          // 唯一入口
fun hasRole(pkg: String, r: AppRole): Boolean
val NEVER_SCAN: Set<String>                   // 由 SHELL ∪ SYSTEM_UI ∪ INERT 派生
```

- `isShell` / `isSystemUi` / `isStore` / `isBrowser` 全部改成 `hasRole(...)` 的薄封装，调用点不动。
- `SkipAccessibilityService.NEVER_SCAN` 删除，改引用 `AppLists.NEVER_SCAN`；`INERT` 收编相册、文件管理、媒体编辑、密码管理器、`com.miui.securitycenter`。
- `JumpGuard.isInUserBlocklist` 保留（它是**用户配置**，不是分类），但挪到 `AppLists.isUserBlocked(pkg, list)`，让「名单」只有一个出处。

**关键约束**：`roles()` 必须允许重叠（商店也可以是 AD_PRONE），但**互斥语义靠断言保证**，不靠 if 顺序：

```kotlin
// 单测：这三个组合不允许同时出现
SHELL ∩ SYSTEM_UI = ∅      // 桌面 ≠ 透明层
SYSTEM_UI ∩ STORE = ∅      // 安装器 ≠ 商店（v1.3.7 事故）
SHELL ∩ STORE = ∅
```

**验收**：现有 74 条单测全绿（这是「行为未变」的唯一证据）；新增 4 条组合不变量。

### 3.2 R1｜systemui 按 className 区分（唯一的真 bug 修复）

**改哪儿**：`JumpGuard.onForeground` 增加第 4 个参数 `className: String? = null`，两个调用点分别透传：
- `SkipAccessibilityService.kt:691`（事件路径，有 `e.className`）
- `SkipAccessibilityService.kt:839`（轮询路径，传 `null`）

```kotlin
private val USER_SURFACE = Regex("(?i)recents|overview|notificationshade|statusbar|quicksettings|globalscreen")

if (pkg == "com.android.systemui") {
    if (GUARD_SYSTEMUI_AS_USER_SURFACE && className != null && USER_SURFACE.containsMatchIn(className)) {
        reset(); lastRealPkg = pkg
        Log.d("AdSkip", "guard shell-surface pkg=systemui cls=$className 清空来源")
    }
    return
}
```

- **正向匹配**，不用「非 heads-up 即用户层」的反向写法（heads-up 通知也是 systemui，反向写会把正在播广告的来源清掉 → 漏拦）。
- `className == null` 时保持旧行为（轮询拿不到 className，宁可不改）。

**单测**（4 条）：
- `systemui + com.android.systemui.RecentsActivity` → 来源被清空
- `systemui + NotificationsShade` → 清空
- `systemui + HeadsUpNotificationView` → 不动
- `systemui + null` → 不动（与 v1.3.9 一致）

**回滚**：常量 `GUARD_SYSTEMUI_AS_USER_SURFACE = true`。

### 3.3 R2｜回访指标 + 影子模式 + 结构化日志

**新增** `data/InterceptLedger.kt`（内存，不落盘）：

```kotlin
data class Intercept(val dest: String, val origin: String?, val at: Long)
fun record(dest: String, origin: String?, at: Long)          // 环形 5 条
fun noteForeground(pkg: String, at: Long, selfRelaunch: Boolean): Intercept?
```

`noteForeground` 逻辑：10 秒内、`pkg == dest`、且不是我们自己 `relaunch` 造成的（用 `restoringPkg` + `restoringAt` 排除）→ 返回命中的那条，调用方写日志：

```
拦截后 6s 用户又回到 com.taobao.taobao，可能拦错了（origin=com.dragon.read）
```

**影子模式**：`Prefs.guardShadow`（默认 false）。判定照跑，但不执行动作、**不污染任何状态**：

```kotlin
if (Prefs.guardShadow) {
    SkipLog.add("【影子】本会拦截 ${pkg.substringAfterLast('.')}：${verdict.reason}")
    return          // 不写 restoringPkg、不更新 lastBackAt、不动 RepeatGuard
}
```

> 这一条是整个方案里最容易写错的地方。影子模式一旦更新了 `lastBackAt` 或 `restoringPkg`，
> 它跑出来的就不是「现行为」而是「现行为 + 影子污染」，数据就废了。单测必须覆盖这三点。

**结构化日志**（新增一行，不动已有前缀，`test_guard.sh` 依赖旧格式）：

```
guard ctx dest=... origin=... dt=... cold=.. splash=.. settled=.. input=..ms adfp=.. mode=..
```

## 4. v1.3.11：撤销入口（R3）

**新增**：`service/GuardNotice.kt`（渠道 `guard_notice`，IMPORTANCE_LOW、无声、无横幅）、`service/UndoReceiver.kt`。

流程：

```
拦截成功 → notify("已拦截一次广告跳转：淘宝 · 来自番茄小说", [撤销] [不再提示], timeout=15s)
点「撤销」→ UndoReceiver → 拉回 dest + 该 dest 熔断 30 分钟 + 日志「用户撤销」
```

**两处必须一并做**：

1. `SkipAccessibilityService` 需要一个可控的静态引用（`WeakReference`）给 Receiver 用；不能在 Receiver 里 new Service。
2. MainActivity 的权限清单加一项 `POST_NOTIFICATIONS`（Android 13+ 需运行时授权）。不加的话，通知在目标机上静默丢弃，用户永远看不到撤销按钮——功能等于没做。

**验收**：拦截后通知出现；点撤销回到落地页；30 分钟内同一目的地不再拦；15 秒后通知自动消失。

## 5. v1.4.0：换证据

### 5.1 R4｜输入溯源（含 1.1 的全屏修正）

**配置**：`accessibilityEventTypes` 增加 `typeViewClicked`。

**新增** `engine/InputTrace.kt`：

```kotlin
data class Tap(val pkg: String, val at: Long, val fullscreen: Boolean)
fun note(pkg: String, at: Long, fullscreen: Boolean)
fun last(): Tap?
```

**service 侧**：

```kotlin
AccessibilityEvent.TYPE_VIEW_CLICKED -> {
    if (now - selfActionAt < 600L) return          // 排除自家点击/手势
    val fs = if (now - coldStartAt < 3_000L) isFullScreenClick(e) else false
    InputTrace.note(pkg ?: return, now, fs)
}
```

`selfActionAt` **直接复用现有的 `lastClickAt`**，但必须补齐三个漏更点：坐标点击 `Access.tapAt`（L1249）、`backOffLanding` 的返回（L526）、三级兜底的返回（L1216 / L1331）。漏一处，一次自动跳过就会造出一个假「用户点击」，之后 1.5 秒内该拦的都不拦了。

**判定**：`Context` 增加 `inputPkg: String?`、`userInputAgoMs: Long`（**默认 `Long.MAX_VALUE`**）、`inputFullscreen: Boolean`；插在 ③（无来源）之后：

```kotlin
if (!c.inputFullscreen && c.inputPkg == c.originPkg && c.userInputAgoMs in 0..1_500) {
    return keep("用户 ${c.userInputAgoMs}ms 前自己点了一下")
}
```

> 默认值传 0 会把整条防跳转全部否决掉（0 落在 `0..1500` 里）。这是这类信号最常见的错法，
> 单测里必须有一条「无输入 → 仍按原判定走」。

### 5.2 R5｜广告指纹（先只记日志）

`SplashScanner` 的 `pageStats` 增加 `adFingerprint`：**一次遍历、零额外 IPC**，命中规则：

```kotlin
// SDK 包名/类名前缀（可信度高）
"com.bytedance.sdk", "com.qq.e", "com.kwad", "com.baidu.mobads", "com.sigmob"
// 已知广告控件 id 前缀
"tt_splash", "ksad", "gdt_", "pangle_", "csj_", "bd_ad", "mimo_"
// 不允许裸子串：`ad_` 会命中 download_ / badge_ / loading_
```

`JumpGuard.noteAdSeen(pkg)` → `adSeenAt`（TTL 8s）→ Context 增加 `originAdSeenRecently`。

**v1.4.0 只把 `adfp=` 写进日志，判定不动。** 跑一周影子数据再决定是否让指纹参与确认。

### 5.3 R6｜两档处置

`Verdict` 增加 `tier: HIGH / LOW`；`Prefs.guardMode` = `COMPAT`（默认）/ `STRICT` / `SHADOW`。

| 档 | HIGH | LOW |
|---|---|---|
| COMPAT（默认） | 回退 | 回退（= 现行为） |
| STRICT | 回退 | 不回退，3 秒提示「疑似广告跳转，已保留」 |
| SHADOW | 只记录 | 只记录 |

### 5.4 R7 / R8 / R10

- **R7**：`c.destIsStore -> c.originAdSeenRecently || (c.originCold && !c.originSettled && c.userInputAgoMs > 1_500)`
- **R8**：事件时刻 80ms 快按 + 400ms 兜底；`relaunch` 1.6s → 1.2s
- **R10**：`(origin, dest)` 配对统计，`intercepts` / `undoOrReturn` / `lastAt`，上限 200 对；两次撤销 → 熔断 30 分钟，再犯 → 24 小时。只影响「拦不拦」，不碰任何名单。
